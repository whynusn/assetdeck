## 任务地图与依赖（显式声明，不靠树位置隐含）

动工顺序（DECISIONS.md 定盘）：**CRUD → 导入归类 → 搜索 → 动效收尾**。

- `crud` 无前置。**`import` 与 `search` 都依赖 `crud` 先落地**：
  - import：归类弹窗的「统一归入」写 category 复用 crud 建立的**窄列 UPDATE category** 通路；回收站落地后所有查询/枚举须带 `deleted=0` 过滤，后到者不得再各自发明过滤。
  - search：FTS5 查询必须排除回收站素材（`Store::search` 加 `deleted=0`），依赖 crud 的 schema v4。
- `motion` 无代码依赖，但**排最后**：它的两段式出场模式将被前三子的新弹层（右键菜单/多选操作条/归类弹窗/范围下拉）直接采用——新弹层出生即正确，motion 负责回改三处旧弹层并统一淡入纪律。
- 若并行，冲突热区：`appwindow.slint`（弹层）、`grid_vm.rs`（选中态）、`main.rs`（装配）。按串行顺序执行即无冲突。
