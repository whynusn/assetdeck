# 视觉与交互设计契约（v1，Fluent 暗/亮基线）

> 本文件是 `ux-audit` 自动化的审查判据。冲突时以 `AGENTS.md` / `DECISIONS.md` 为准。
> 版本：v1（2026-10-23 由现有实现反推）。**只能按 §9 收紧，不能为让问题通过而静默放宽。**

## 0. 产品气质

安静、精确、可信。素材是主角，界面 chrome 退后；高频动作（搜索、双击上框、多选、归类）路径短且反馈即时；
危险动作（清空、彻底删除、删除分类）有明确隔离与二段确认。拒绝“到处补丁式”的局部特判与魔法数字。

## 1. Token 契约

### 1.1 颜色

只允许消费 `theme.slint` 的 `Theme` 令牌；`crates/app-ui/ui/**` 中新增任何十六进制色值都视为违规（`theme.slint` 的令牌定义除外）。

| 角色 | 令牌 | 用途 | 禁止 |
|---|---|---|---|
| 窗口底 | `bg-app` | 窗口背景 | 用面板色冒充窗口底 |
| 面板 | `bg-panel` | 侧栏/内容面板 | |
| 条 | `bg-bar` | 顶栏/底栏 | |
| 抬起面 | `bg-raised(-hover/-press)` | 按钮、菜单行、次级面 | |
| 输入底 | `bg-input` | 搜索框等 | |
| 浮层 | `bg-overlay` | 弹窗/菜单/设置面板 | 与 `bg-raised` 混用 |
| 描边 | `line` / `line-strong` | 常态 / 悬停与强调边界 | 用文本色当描边 |
| 文本 | `text` / `text-2` / `text-3` | 主 / 次 / 弱 | `text-3` 用于可操作文字或主信息 |
| 强调 | `accent` / `accent-hover` / `accent-press` / `accent-ink` / `accent-soft` | 选中、焦点、主按钮 | 用白色描边表示选中 |
| 危险 | `danger` / `danger-soft` / `danger-press` | 删除/清空 | 危险色用于普通强调 |
| 警告 | `warn` / `warn-soft` | 需注意但未失败 | |
| 成功 | `ok` / `ok-soft` | 成功、已送达 | **当前缺失，须补 token**；禁止再用 `#5ac18e` |
| 共享 | `shared` / `shared-soft` | 「共享中」状态 | **当前缺失，须补 token**；禁止再用 `#be4bdb` |
| 角标 | `label-bar-*` / `badge-*` / `card-icon` | 瓦片名称条/徽标/缺图图标 | |
| 遮罩 | `scrim` | 弹窗背景 | 用纯黑不透明 |

补充规则：
- 选中/激活统一用 `accent`（描边或 soft 底），不得使用 `#ffffffcc` 之类的高亮白。
- 语义色必须成对提供 soft 变体（暗/亮两套），保证可读。
- 状态不能只靠颜色：选中、错误、共享中都要同时有形状/图标/文字中的至少一种冗余线索。

### 1.2 字体阶梯

新增 `Typography` token（Slint 属性或 global），界面一律消费 token，禁止 `font-size` 内联字面量。

| 角色 | 字号 | 字重 | 用途 |
|---|---|---|---|
| display | 16px | 600 | 主读数（总数）、关键弹窗标题 |
| title | 14px | 600 | 面板/模块标题、顶栏主信息 |
| body | 12px | 400 | 正文、按钮、列表主行 |
| label | 11px | 500 | 次级按钮、范围段、上下文标签 |
| caption | 10px | 400 | 仅限次要元数据；不得承载唯一关键信息 |

- 行高：正文 ≥ 1.4×；单行控件用居中对齐，不写死行高。
- 同一层级不得出现 10/11/12/13/14 随意混用；13px 视为过渡档，逐步归并到 12/14。
- 长文本必须 `overflow: elide` 或 `wrap: word-wrap`，并给 Tooltip 兜底。

### 1.3 间距、尺寸、圆角、图标

- 4px 基准网格；间距只取 `2/4/6/8/10/12/16/20/24`（2px 为半档）。14px 为历史遗留，新代码不得使用。
- 控件高度：紧凑 28px、标准 30px、主操作 32px；图标按钮 30×30；开关 40×22；菜单行 46px；顶栏/底栏 48px。
- 可点击热区 ≥ 28×28px；图标按钮之间 ≥ 6px；危险按钮与常规按钮之间 ≥ 8px 或独立分组。
- 圆角：控件 4px（`radius`）、面板/弹窗 8px（`radius-lg`）、开关胶囊 = 高度/2、滑块 7px。
- 描边：常态 1px `line`；焦点/激活 1px `accent`；不使用 2px 以上描边（除非焦点环方案统一落地）。
- 图标：24 单位视图盒、1.7px 描边、圆头圆角；尺寸取 `10/12/13/14/15/16/20`；同一语义只能用一个字形。
- 图标与文字基线/光学中心对齐；图标-only 按钮必须有 Tooltip。

### 1.4 动效

- 微交互（hover/press）：100–120ms；状态切换（开关/选中）：120–140ms；浮层入场：150ms；出场可即时或 ≤150ms。
- 只允许 `ease-out`（入场/状态）与线性（滚动/进度）；不使用弹跳/回弹。
- 设置项「界面动画」关闭时，所有 `animate` 时长必须归零（`root.animations-enabled ? Nms : 0ms`）。
- 动效不得阻塞输入；不得为动画引入定时器轮询。

## 2. 组件契约

### 2.1 状态矩阵（所有可交互原语）

按优先级实现：`disabled > pressed > selected/active > hover > default`。
- **disabled**：降低对比、禁用命中、光标不变 pointer；不得只把文字变灰而保留可点。
- **hover**：背景或描边至少一项变化；行类控件铺淡底，不画成按钮。
- **pressed**：比 hover 更深/更暗，松手恢复。
- **selected/active**：accent 描边或 soft 底，二者至少一项；与 hover 可叠加但不得互相覆盖。
- **focus**：键盘焦点必须可见（1px accent 描边或统一 focus ring），且与 hover 可区分。
- **busy/loading**：有进行中指示；禁止重复触发；完成后清除。
- **error**：就地提示（输入框下方/行内），文案可行动；不得只弹全局 toast。

### 2.2 焦点与键盘

- `Tab` 顺序 = 视觉顺序；弹窗打开后焦点进入弹窗，关闭后回到触发控件。
- `Esc` 永远能关闭最上层浮层（capture 优先级）；模态链按 `modal-open` 单一事实来源。
- `Enter` 在单输入弹窗 = 确认；`Space` = 切换复选框/开关；`Ctrl+A` = 多选全选（先进入多选模式）；`Ctrl+V` = 粘贴导入。
- 输入框持焦时，全局快捷键不得抢键（除 Esc）。
- 禁用控件不可获得焦点；错误提示可被读屏/键盘触达。

### 2.3 弹窗与菜单

- 弹窗水平居中：`x = (root.width - width) / 2`；垂直居中并夹取：`y = Math.max(16px, (root.height - height) / 2)`。
- 宽 320–420px；最大高度 ≤ 窗口高 − 32px，内容超出内部滚动；不得顶出窗外或压到底栏。
- 背景遮罩统一 `scrim`；浮层用 `bg-overlay` + 1px `line-strong` + 16px 柔和投影。
- 点击外部策略遵循 D67：菜单/设置点外部收起；工作流弹窗（归类/重命名/共享确认）只挡不关。
- 菜单行无描边、悬停淡底；每行高度 ≥ 40px；危险项独立分组/分隔线。
- 弹窗打开时背景不可操作（模态）；`import-result` 等非模态面板按现有语义处理。

### 2.4 反馈与安全

- 任何写操作在 100ms 内给出可见反馈（按下态/进度/禁用）。
- 破坏性操作：二段确认（armed）或明确确认弹窗；默认焦点不在危险按钮；破坏性动作不得与常规动作紧邻无隔离。
- 失败必须说明「发生了什么 + 下一步」；不得暴露内部状态名/协议名/Dxx 编号。
- 空态必须给出下一步动作（导入、清除搜索、切换分类等），不能只写“暂无数据”。

## 3. 布局与适配

- 目标窗口：1000×700 默认；最小 960×600；在此尺寸下三栏不重叠、不裁切、弹窗可完整操作。
- 侧栏可拖拽 150–420px；分栏边界不吞点击，拖拽光标正确，松手持久化。
- 窗口缩放时内容区自适应；禁止用绝对坐标堆叠主布局（弹窗锚点除外）。
- 真实数据压力：分类名 ≥ 20 字、文件名 ≥ 60 字、0/1/10 万条、混合图片/视频/文本/文件。
- 文本截断有 Tooltip；数字使用千分位（如 `1,248`）。
- 150% DPI 下不模糊、不裁切；多显示器拖动后窗口不越界。

## 4. 文案与术语

遵循 `CONTEXT.md`：素材、上框、分类、待分类、回收站、共享、主题包。
- 动作按钮用动词（导入素材、移动到分类、复制本次日志），不用“确定/提交”这类空泛词。
- 不使用内部术语：Dxx、VM、子进程、协议、注入、payload、hwnd。
- 错误文案 = 现象 + 影响 + 下一步；例：「无法读取剪贴板中的文件：请确认文件仍存在，或改用导入素材」。
- 中文标点统一全角；中英文之间按现有风格留空格；省略号用 `…`。
- Tooltip 讲“做什么/为什么”，不重复按钮文案。

## 5. 可访问性

- 文本对比度：< 18px 正文 ≥ 4.5:1；大字号/UI 边界 ≥ 3:1；`text-3` 在 `bg-raised` 上必须实测达标，否则改用 `text-2`。
- 焦点可见、非颜色唯一线索、可键盘完成全部主流程。
- 动画可关闭；不闪烁；不使用 < 100ms 的高频闪烁。
- 热区 ≥ 28px；图标按钮有可读名称（Tooltip/可访问文本）。

## 6. 性能预算（UI 侧）

- 空闲 RSS ≤ 100MB；10 万条浏览 ≤ 250MB；不因视觉改动引入常驻缓存/新依赖。
- 网格虚拟化；不为每个瓦片创建昂贵对象；不在滚动/悬停路径做全量模型重建。
- 缩略图解码/抽帧不进 UI 进程；视觉层只消费已派生资源。
- 动画只改 opacity/transform/颜色等轻量属性，避免每帧重排整棵树。

## 7. 证据与完成定义

每个组件审查必须留下：
1. 审查时的源码锚点与 `auditedAtCommit`。
2. 至少 1 张真实状态截图（`target/ux-audit/shots/<component>/<before|after>/`），修复前后各一。
3. 发现项（finding）必须写明：现象 → 根因层（token/primitive/layout/viewmodel/platform/copy）→ 修复位置 → 验证方式。
4. 验证门禁全过（见 runbook §1.6）。

组件“完成”= 无开放 P0/P1；P2/P3 可留档但必须写明不修理由或后续组件。
模块“完成”= 组件全 done，且跨组件一致性复核通过。

## 8. 根因层与反补丁判定

| 根因层 | 正确修法 | 反例（禁止） |
|---|---|---|
| token | 在 `theme.slint` 补令牌并全局替换 | 在单个界面写一个新色值 |
| primitive | 改 `theme.slint` 原语的状态/尺寸 | 在某个调用点加 `if` 改颜色 |
| layout | 用容器/绑定推导位置与尺寸 | 给某个弹窗再写一个魔法 y |
| viewmodel | 在 `ui-viewmodels` 增加具名状态/枚举 | 在 .slint 里堆布尔组合特判 |
| platform | 在 `platform` 统一窗口/焦点行为 | 每个弹窗各写一份 Esc/焦点逻辑 |
| copy | 收口文案与术语 | 同一概念三种叫法 |

判定规则：
- 同一字面量/同一状态在 ≥2 处出现 → 必须收口到 token/primitive，不接受逐处修。
- 修复引入的新条件分支若无具名不变量，视为补丁。
- 每类可机械检测的问题，优先补 guard（测试/扫描），再修个案。

## 9. 契约修订

- 自动化可以提出修订，但必须在 `journal.md` 写明：条款、现状证据、为什么现有契约不合理、影响面。
- 放宽阈值/例外必须单独一次运行、单独提交，并在 commit message 标注 `contract:`；不得与功能修复混在一起。
- 任何修订都不得降低 `AGENTS.md` 的红线（上框语义、auto-send 默认关、无 0x0D、焦点校验、进程模型、内存预算）。
